## 2026-01-11 - DOM-Based XSS in Dynamic Event Handlers
**Vulnerability:** A critical XSS vulnerability was identified in `src/classes/filesystem.class.js` where file/device paths were directly interpolated into `onclick` attribute strings: `` cmd = `... "${e.path.replace(/\\/g, '')}" ...` ``. This allowed malicious path names (e.g., from USB drives) to break out of the JavaScript string context and execute arbitrary code.
**Learning:** Using data directly in dynamically generated code strings is dangerous, especially when the context is complex (HTML attribute -> JavaScript string). Even simple escaping can be easily missed or incorrect (e.g., regex backslash escaping complexity). The vulnerability persisted because the `render` method relied on global state (`fsDisp.cwd`) which was not synchronized when viewing devices, forcing the original author to use direct string injection for devices instead of safe index lookups.
**Prevention:**
1.  **Prefer Index-Based Lookups:** Instead of embedding data, embed an index to an array (e.g., `fsDisp.cwd[i]`) and ensure the array is synchronized with the view. This keeps the data completely out of the generated code string.
2.  **Synchronize State:** Ensure that the data model (`this.cwd`) always reflects the UI state, enabling consistent and safe data access patterns across different view modes.
3.  **Strict Context Escaping:** If direct injection is unavoidable, rigorous context-aware escaping must be applied. For regex inside template literals, quadruple escaping (`\\\\`) is often required to produce a single backslash literal in the output.
