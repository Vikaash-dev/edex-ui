## 2025-01-04 - [XSS in Event Handler String Interpolation]
**Vulnerability:** User-controlled filenames were properly HTML-escaped (`_escapeHtml`) but then directly interpolated into JavaScript code strings within `onclick` attributes. This allowed attackers to use backslashes (`\`) to escape the closing quote of the JavaScript string and inject arbitrary code, because HTML entity decoding happens *before* JavaScript parsing in event handlers.
**Learning:** `window._escapeHtml` protects against HTML injection (breaking out of the attribute), but it does not protect against escaping the JavaScript string context *inside* the attribute. Specifically, `&quot;` becomes `"` after HTML decoding, and `\` is not escaped by `_escapeHtml`.
**Prevention:** When interpolating data into inline event handlers, use a dedicated JavaScript escaping function (like `_escapeStringForJS`) *before* the HTML escaping, or preferably, avoid inline JavaScript generation with user input altogether (use `addEventListener` or pass indices/IDs instead of raw strings).
